# 周转箱仓点调拨策略仿真

事件引擎按时间重放入箱 / 租借 / 归还流，在**同一需求版本**下对照两套调拨规则，
输出缺箱时长与空驶量；并提供「晚到归还」对照版本。纯 Node.js 内置模块实现，不接外部服务。

## 启动

```bash
node server.js          # 默认端口 3000
PORT=3100 node server.js # 读取 PORT，仅绑定 127.0.0.1
# 打开 http://127.0.0.1:3100
```

## 测试

```bash
node --test 'test/**/*.test.js'
# 或
npm test
```

45 个用例，覆盖正常结果（事件流、缺箱时长、空驶里程、争用裁决、晚到对照、HTTP 端到端）
与异常结果（非法事件类型、时间倒流、负库存、未知仓点、自环距离、零容量、非法 JSON 等）。

## 页面操作（同一次会话内三个结果区同时保留，可前后核对）

| 按钮 | 接口 | 结果区 `data-evidence-result` |
|---|---|---|
| 运行基准策略 | `POST /api/compare` | `baseline-comparison` |
| 补迟到归还并比较 | `GET /api/late-return` | `late-return-comparison` |
| 查看调拨时点 | `GET /api/timeline` | `dispatch-timeline` |

每个结果附 12 位 SHA-256 **校验签名**（事件流 + KPI），用于核对前后两次操作数据是否同源。

## 模型与规则

- **事件**：`intake`（入箱）、`rental`（租借）、`return`（归还）分别入流，时间非降排列。
- **因果性（题眼）**：策略 `decide()` 只接收当前时刻快照（在手库存、积压、在途、车辆状态），
  引擎从不传入未来事件，因此**不可能用未来归还弥补当时缺箱**。
- **两套调拨策略**（同一事件流、同一组 KPI）：
  - `immediate` 低水位立即调拨：有效库存（在手 + 在途）跌破低水位或出现积压即补到目标水位；
  - `batch` 批量阈值调拨：容忍先积压，跌破更激进的批量阈值才凑大批量一次补到目标水位，
    用更多缺箱时长换更少的发车次数与空驶里程。
- **单车次争用**：全局一台车，同刻多仓申请按
  「当前积压量大 → 申请时间早 → 仓 id 字典序」裁决，负方申请保留排队，全过程写争用日志。
- **里程口径**：车辆空驶到捐箱仓记空驶段，载货去目的仓记重载段；
  捐箱仓须自身无积压且划出箱量后不跌破自身低水位。
- **缺箱口径**：租借未满足量形成 FIFO 积压，缺箱时段从积压产生计到清偿；
  入箱/归还/调拨到达均先清偿积压。
- **晚到归还**：同一事件骨架中 B 仓一笔 6 箱归还由 t=70 延迟到 t=100，
  受影响时段取半开区间 `[70, 100)`，只统计与窗口相交的缺箱时长。

## 样例的关键结论（可手工复核）

- 基线：立即策略 105 分钟缺箱 / 100 km 空驶 / 5 趟；批量策略 105 分钟 / 70 km / 4 趟——
  批量策略省 30 km 空驶、少发一趟车。
- 晚到 30 分钟：立即策略 KPI **零变化**（本就按低水位补箱，不依赖该笔归还）；
  批量策略受影响窗口缺箱 +10 分钟、总缺箱 +10 分钟。
- 晚到后两仓在 t=80 的积压结构发生变化（基线 B 缺 2 箱，晚到版 B 缺 8 箱），
  争用裁决明细与每趟车次的胜/负原因可在「调拨时点」面板逐趟核对。

## 目录结构

```
server.js              服务入口（读 PORT，绑定 127.0.0.1）
lib/
  validation.js        场景校验（异常输入 -> 中文原因）
  scenario.js          本地样例（baseline / late 两个需求版本）
  strategies.js        两套调拨策略（只看当前快照）
  engine.js            时间重放事件引擎、车辆与争用裁决
  compare.js           同版本策略对照、晚到对照、调拨时点、签名
  http-handler.js      静态页 + JSON API
public/                原生 HTML/CSS/JS 页面（无图表库、无外部依赖）
test/                  node:test 用例
```
